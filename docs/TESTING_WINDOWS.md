# Marjon — тестирование на Windows (с нуля)

Инструкция для запуска и реального теста в локальной сети: веб, админка, десктоп-касса,
мобильные приложения и печать чеков.

---

## 0. Что нужно установить (один раз)

| Что | Зачем | Проверка |
|---|---|---|
| **Node.js 20+** | веб, админка, десктоп | `node -v` |
| **Python 3.12** | бэкенд | `py -3.12 -V` |
| **Git** | обновление кода | `git --version` |
| Flutter SDK (опционально) | только для mobile/owner | `flutter --version` |

> **Python:** целевая версия проекта — **3.12** (см. `backend/Dockerfile`). На 3.13/3.14
> часть пакетов может не собраться. Если venv создан на 3.14 и что-то падает:
> ```powershell
> cd C:\Users\x\Desktop\Marjon\backend
> Rename-Item .venv .venv_old
> py -3.12 -m venv .venv
> .\.venv\Scripts\python.exe -m pip install -r requirements.txt
> ```

> **Flutter (если нужны mobile/owner):** `winget install --id Google.Flutter -e`,
> затем перезапустить терминал и выполнить `flutter doctor`.

## 2. Запуск

Правой кнопкой по **`start.cmd`** → **«Запуск от имени администратора»**
(права нужны, чтобы скрипт сам открыл порты в фаерволе).

Выбрать пункт:

| Пункт | Что запускает |
|---|---|
| `1` | веб + админка + бэкенд |
| `2` | десктоп-касса + бэкенд |
| `5` | всё вместе |
| `6` | только бэкенд |

Скрипт сам: покажет IP компьютера, добавит правила фаервола (8000/5173),
пропишет адрес API для веба, поставит зависимости при нехватке, поднимет
бэкенд на `0.0.0.0` и дождётся порта 8000.

**Миграции** (вопрос при старте): отвечать `y` при первом запуске или после
`git pull` с изменениями схемы. Если таблицы уже есть, а alembic ругается
`table ... already exists` — скрипт предложит `alembic stamp head`, согласиться.

Каждый сервис работает в своём окне. **Закрыть сервис = закрыть его окно.**

## 3. Проверить сеть

1. Профиль сети должен быть **«Частная»**: Параметры → Сеть и Интернет →
   свойства сети → Частная. На «Общедоступной» правила фаервола не действуют.
2. С компьютера: открыть `http://localhost:8000/docs` — должен открыться Swagger.
3. С телефона/планшета (тот же Wi-Fi): открыть `http://<IP>:8000/docs`,
   где `<IP>` — адрес, который напечатал скрипт.

Если с телефона не открывается, а с ПК открывается — дело в сети (изоляция
клиентов в гостевом/корпоративном Wi-Fi) или в фаерволе, не в коде.

## 4. Адреса

| Куда | Адрес |
|---|---|
| Веб (ПК) | `http://localhost:5173/` |
| Админка (ПК) | `http://localhost:5173/admin.html` |
| Веб с планшета | `http://<IP>:5173/` |
| API / Swagger | `http://localhost:8000/docs` |
| Адрес сервера для десктопа на этом ПК | `http://localhost:8000/api/v1` |
| Адрес сервера для десктопа/мобилки на другом устройстве | `http://<IP>:8000/api/v1` |

> После смены адреса сервера в десктопе **перезапустить приложение**: WebSocket
> (живая кухня, печать) создаётся один раз при входе и старый адрес не меняет.

## 6. Настройка принтеров (на сайте)

Веб → **Настройки → Принтеры** (`/settings/printers`) → **«Добавить принтер +»**

| Поле | Что указать |
|---|---|
| Название | например «Касса» |
| Тип принтера | **Чековый** (клиентские чеки) или **Кухонный** |
| Филиал | обязательно — принтер привязан к филиалу |
| IP | IP принтера в локальной сети |
| Порт | `9100` (стандарт ESC/POS) |
| Ширина бумаги | **58 мм** или **80 мм** — иначе чек «поедет» по ширине |
| Статус | Активно |

## 7. Как работает печать (важно понимать при тесте)

1. Бэкенд формирует ESC/POS и **сам** пытается отправить его на `IP:9100`.
   → Значит принтер должен быть доступен **с машины, где работает бэкенд**.
2. Если бэкенд не смог — задание остаётся в статусе `pending` и рассылается
   терминалам филиала по WebSocket. Терминал печатает локально сам.
3. `print_agent` (отдельный Python-мост) опрашивает `pending`-задания — вариант,
   когда бэкенд в облаке, а принтеры в заведении.

**Авто-печать:** только **кухонный** чек (при создании заказа и добавлении позиций).
Клиентский чек печатается **кнопкой** «Печать».

⚠️ **Не запускать `print_agent` одновременно с десктоп-терминалами** на те же
принтеры — оба могут взять одно задание и напечатать дважды.

### Проверка принтера

С машины бэкенда:
```powershell
Test-NetConnection <IP_принтера> -Port 9100
```
Нужно `TcpTestSucceeded : True`.

Либо в десктопе: **Настройки → Принтеры (диагностика) → Пинг**

| Значок | Смысл |
|---|---|
| `✓` | сервер видит принтер → печать пойдёт напрямую |
| `✓*` | сервер не видит, но видит терминал → печать пойдёт через терминал |
| `✕` | не видит никто → проверить IP, порт, сеть |

## 8. Порядок проверки

1. Веб на ПК → вход владельцем → данные загружаются.
2. Настроить принтеры (раздел 6).
3. Пинг принтеров: должно быть `✓` или `✓*`.
4. Десктоп: адрес сервера → войти админом → выбрать филиал → выбрать сотрудника → PIN.
5. Создать заказ в кассе → **кухонный чек печатается автоматически**.
6. Нажать «Печать» в заказе → **клиентский чек**.
7. Провести оплату → чек, отчёты.
8. Веб с планшета по `http://<IP>:5173/`.

## 9. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `ModuleNotFoundError: <пакет>` | venv устарел | `cd backend` → `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` |
| `Cannot find module 'ws'` (десктоп) | node_modules устарел | `cd desktop` → `npm install` |
| `table ... already exists` при миграции | alembic не проинициализирован | согласиться на `alembic stamp head` |
| Ошибка про `pin_hash` при PIN-входе | не выполнена миграция | `cd backend` → `.\.venv\Scripts\python.exe migrate_add_permissions.py` |
| Веб с планшета: страница есть, данных нет | CORS | перезапустить бэкенд после `git pull` (лаунчер передаёт LAN-адрес в `ALLOWED_ORIGINS`) |
| С планшета не открывается `:8000/docs` | фаервол / профиль сети / изоляция клиентов Wi-Fi | раздел 3 |
| Чек не напечатался | принтер недоступен с сервера | смотреть окно бэкенда; задание остаётся `pending` и уйдёт на терминал |
| Живая кухня не обновляется после смены адреса сервера | WS держит старый адрес | перезапустить десктоп |
| Белый экран в десктопе | ошибка рендера | `Ctrl+Shift+I` → Console → скопировать красную ошибку |

## 10. Ограничения текущего состояния

- Печать проверена только по коду — физическую распечатку нужно проверять на
  реальном принтере (58 и 80 мм, длинные названия, много позиций).
- Preview чека в интерфейсе **не доказывает** корректность физической печати.
- Задания к недоступному принтеру копятся в `pending` без срока давности.
- Мобильные приложения хранят токен в открытом хранилище (не для продакшена).
