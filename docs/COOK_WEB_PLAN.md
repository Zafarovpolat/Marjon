# Отдельная веб-страница для поваров (вне десктопа/админки/мобилы)

> Статус: **MVP реализован** (2026-10-24). Экран кухни — отдельный Vite-entry
> `frontend/kitchen.html` → `src/kitchen/main.jsx`, свой бандл, свой адрес.
> Десктоп и админка кухню больше не показывают.
>
> Рабочие адреса: `https://admin.marjon.tech/kds` (сейчас) и
> `https://kitchen.marjon.tech` (после DNS-записи и расширения сертификата).

## Что сделано

1. **Backend: кухонная сессия с урезанным скоупом** (`auth_scope="kitchen"`).
   - `POST /auth/kitchen/session` — логин+пароль филиала → сессия терминала.
     Вводится один раз при настройке экрана.
   - `POST /auth/kitchen/pin` — PIN повара → его собственная сессия. Ищем
     только внутри филиала терминала и только среди роли `kitchen`, поэтому
     PIN кассира кухонный экран не открывает.
   - `get_current_user` не пускает кухонный токен никуда, кроме
     `/api/v1/kitchen/*` и служебных `/auth/me|refresh|logout|kitchen/pin`.
     `/auth/refresh` сохраняет скоуп — продление не повышает права.
   - `require_kitchen_access` пускает на кухню и повара (kitchen-скоуп), и
     владельца/менеджера (обычный app-скоуп).
   - `PATCH /kitchen/orders/{id}/ready` — «весь заказ готов» без выхода в
     `/pos` (для kitchen-скоупа он закрыт). Заказ в `new`/`accepted` сначала
     переводится в `cooking`: перепрыгнуть кухню нельзя (state machine).
   - WS `/ws/kitchen` принимает kitchen-скоуп и запрещает подписку на чужой
     филиал.

2. **Frontend: отдельный экран** (`frontend/src/kitchen/`).
   - Экран настройки устройства: логин+пароль филиала.
   - Экран входа повара: PIN из 4 цифр, крупная клавиатура, авто-отправка на
     четвёртой цифре, сообщение о блокировке после серии ошибок.
   - Доска заказов: карточки с таймером (жёлтый >10 мин, красный >20),
     «Готовить» / «Готово» по блюду, «ЗАКАЗ ГОТОВ» по заказу.
   - WebSocket + резервный опрос каждые 5 сек, звук на новый заказ,
     fullscreen, «Сменить повара» (PIN следующего), «Сброс» (перепривязка
     экрана к другому филиалу).

3. **Десктоп: повара убраны.**
   - `MODES` = cashier/waiter/courier, режима кухни в бандле нет.
   - `roleToMode()` для кухонной роли возвращает `null` → вход отклоняется с
     подсказкой про кухонный экран (раньше молча открывалась касса).
   - В списке сотрудников повара скрыты, внизу подсказка с адресом экрана.

4. **Админка:** `KitchenPage.jsx` не подключён ни к одному маршруту, `/kitchen`
   в SPA редиректит на логин — владелец кухню в вебе не открывает.

5. **nginx:** `location = /kds` на `admin.marjon.tech` отдаёт `kitchen.html`;
   `nginx/conf.d/kitchen.conf` — отдельный хост `kitchen.marjon.tech`
   (включается после DNS).

## Что осталось (не блокирует запуск)

| # | Задача | Зачем |
|---|--------|-------|
| 1 | DNS `kitchen.marjon.tech` + `certbot --expand` + reload nginx | Короткий адрес вместо `admin.marjon.tech/kds` |
| 2 | Offline-очередь «Готово» (localStorage + replay) | Кухня — зона плохого Wi-Fi |
| 3 | Фильтр по станциям (`GET /kitchen/stations` уже есть) | Повар видит только свои блюда |
| 4 | Настройки экрана (пороги таймеров, звук) в localStorage | Разные кухни — разные нормативы |
| 5 | Мобила: скрыть кухонный режим для роли `kitchen` | Повар заходит через веб |
| 6 | Шеф-повар: обзор всех станций + стоп-лист с экрана | Роль шире, чем у повара |

## Как включить экран на кухне

1. Открыть `https://admin.marjon.tech/kds` (после DNS — `https://kitchen.marjon.tech`).
2. Ввести логин и пароль филиала (те же, что на десктопе) → «Подключить экран».
3. Повар вводит свой PIN из 4 цифр → видит заказы филиала.
4. «Во весь экран» — для кухонного монитора. «Сменить повара» — конец смены.

PIN задаётся владельцем в веб-админке: «Сотрудники» → карточка повара → PIN
(роль должна быть «Повар», иначе кухонный экран её не примет).
