# План: Отдельная веб-страница для поваров (вне десктопа/админки/мобилы)

> Статус: **НЕ реализовано** (на момент 2026-10-18).
> Текущая реализация — kitchen-экран встроен в десктоп (`KitchenMode.jsx`),
> веб-админку (`KitchenPage.jsx`) и мобилу (`kitchen_mode.dart`).
> Ниже — аудит + план выделения отдельной независимой веб-страницы.

## Что уже есть сейчас

1. **Backend kitchen-модуль** (`app/modules/kitchen/`) — полностью готов:
   - `KitchenConnectionManager` — WebSocket с Redis pub/sub (`kitchen:{company}:{branch}`),
     multi-worker safe, с in-process fallback.
   - `GET /kitchen/orders?branch_id=…` — активные заказы (`new`/`accepted`/`cooking`).
   - `PATCH /kitchen/orders/items/status` — отметка блюда готовым/отменённым.
   - `POST /kitchen/stations` / `GET /kitchen/stations` — станции по категориям.
   - State machine: `pending → cooking → ready → served` (+ `cancelled`).
   - WS-эндпоинт `/ws/kitchen?token=…&branch_id=…` — авторизация по JWT.
   - Broadcast-события: `new_order`, `order_updated`, `order_cancelled`, `item_status_changed`.

2. **Веб KitchenPage** (`frontend/src/pages/KitchenPage.jsx`) — есть, но **внутри админки**:
   - Рендерит карточки заказов с таймерами (зелёный < 5 мин, жёлтый 5–10, красный > 10).
   - Кнопка «Tayyor» на каждое блюдо → `PATCH /kitchen/orders/items/status`.
   - Кнопка «BUYURTMA TAYYOR» (весь заказ готов) → `PATCH /pos/orders/{id}/status`.
   - WS-подключение + fallback polling 5 сек.
   - Авто-печать кухонного чека при новом заказе (если включено в настройках).
   - **Проблема**: для доступа нужен логин owner/admin → нельзя дать повару.

3. **Десктоп KitchenMode** (`desktop/src/modes/kitchen/KitchenMode.jsx`) — есть, но **не активирован**:
   - Полностью написан (optimistic updates, звуки, overdue-алерты, стоп-лист, рецепты).
   - **НЕ зарегистрирован** в `MODES` в `desktop/src/App.jsx` (только `cashier`, `waiter`, `courier`).
   - Нет в `ROLE_TO_MODE` → повар не может зайти в десктоп.
   - Owner хочет: «убрать повар с десктопа» → этот режим не должен активироваться.

4. **Мобила kitchen_mode.dart** — порт десктопной версии, тот же WS + API.

5. **Настройки чека** (`settings/ChefReceiptSettingsPage.jsx`) — конфигурация кухонного чека.

## Чего не хватает

| # | Функция | Почему важно |
|---|---------|--------------|
| 1 | **Отдельная точка входа** — независимый URL без логина в админку | Повар не должен иметь доступ к финансам, настройкам, отчётам |
| 2 | **Простая авторизация повара** — PIN-код или логин/пароль | Быстрый вход у плиты, без полного JWT-флоу |
| 3 | **Только кухонные экраны** — заказы, статусы блюд, «Готово» | Ничего лишнего, крупный шрифт, тач-френдли |
| 4 | **Звук + визуальные алерты** — новый заказ, overdue | Повар не смотрит на экран постоянно, нужен звук |
| 5 | **Offline-очередь** — кнопки «Готово» не теряются при сбое сети | Кухня — зона плохого Wi-Fi, пишет не должны пропадать |

## Пошаговый план реализации

### Этап 1 — Backend: авторизация повара (0.5 дня)

- Добавить `POST /auth/kitchen-login`:
  - Принимает `branch_id` + `pin_code` (или `login` + `password` филиала);
  - Проверяет PIN-код сотрудника (`User.pin_hash`) или пароль филиала;
  - Проверяет, что у сотрудника есть доступ к кухне (например, роль `cook`
    или разрешение `modules.kitchen.enabled`);
  - Выдаёт `access_token` с `auth_scope="kitchen"`, `branch_id`;
  - Токен ограничен: только `/kitchen/*` и `/ws/kitchen`.
- Добавить dependency `require_kitchen_token`:
  - Проверяет `auth_scope == "kitchen"`;
  - Автоматически подставляет `branch_id` из токена;
  - Отклоняет запросы к другим модулям.

### Этап 2 — Frontend: отдельная страница (1 день)

- Новый Vite entry-point: `frontend/src/kitchen-app.jsx` → отдельный bundle.
- Отдельный маршрут в nginx: `kitchen.marjon.tech` (или `/kitchen/` путь).
- Страница входа: поле выбора филиала + PIN-код, крупный шрифт, авто-фокус.
- После входа — `KitchenDashboard`:
  - Карточки заказов (reuse `KitchenOrderCard` из текущего `KitchenPage.jsx`);
  - WS-подключение к `/ws/kitchen` с токеном повара;
  - Звуки: новый заказ (длинный бип), overdue (повторяющий короткий);
  - Таймеры: зелёный < 5 мин, жёлтый 5–10, красный > 10, мигающий > 15;
  - Кнопка «Tayyor» на каждое блюдо → `PATCH /kitchen/orders/items/status`;
  - Кнопка «BUYURTMA TAYYOR» (весь заказ);
  - Полноэкранный режим (fullscreen API), блокировка прокрутки;
  - Авто-обновление каждые 5 сек (fallback если WS упал).

### Этап 3 — Frontend: offline-очередь (0.5 дня)

- Адаптировать `writeQueued` из десктопа в веб-версию:
  - `localStorage` очередь для `PATCH /kitchen/orders/items/status`;
  - При reconnect — replay всех отложённых запросов;
  - Индикатор «офлайн» в углу экрана (жёлтый бейдж + счётчик отложенных).

### Этап 4 — Убрать повара из десктопа (0.5 дня)

- В `desktop/src/App.jsx`:
  - `KitchenMode` уже **не зарегистрирован** в `MODES` — оставить как есть;
  - Убрать `kitchenWS.connect()` из глобального `useEffect` (или оставить
    только если пользователь — кассир/официант, чтобы принимать уведомления);
  - Удалить `ROLE_TO_MODE["cook"]` если есть (сейчас нет — ОК).
- В `desktop/src/modes/kitchen/` — оставить файлы, но не импортировать
  в прод-бандл (tree-shaking уберёт, если нет импорта).

### Этап 5 — Mobile: оставить или убрать (решить) (0.5 дня)

- `mobile/lib/src/features/kitchen/kitchen_mode.dart` — сейчас работает.
- Опция A: оставить (вдруг нужен мобильный kitchen fallback).
- Опция B: убрать (раз есть отдельная веб-страница).
- Рекомендация: **оставить**, но скрыть для роли `cook` в мобиле — пусть
  повар заходит через веб-страницу.

### Этап 6 — Настройки и конфигурация (0.5 дня)

- В админке: настройки kitchen-дисплея (пороги таймеров, звуки, шрифт).
- Сохранять в `localStorage` браузера повара (не нужны права админки).
- Печатать кухонный чек при новом заказе — только если в настройках
  филиала включено `kitchenTemplate.autoPrint`.
