# Физическая приёмка чеков — чек-лист (58мм и 80мм)

Это ручной чек-лист для проверки на **настоящем** ESC/POS принтере — автотесты
(`tests/test_receipt_formatter.py`, `tests/test_receipt_parity_integration.py`)
проверяют байты, которые формирует бэкенд, но не то, как они реально лягут на
термобумагу конкретной модели принтера. `REAL_PRINTER_TESTED = NO` на момент
этой сдачи — физического принтера в среде разработки нет.

## Как получить сырые байты для печати

Самый быстрый способ прогнать реальный чек без похода в БД — вызвать
формогенератор напрямую и отправить результат на принтер (по сети через
`nc`/`Test-NetConnection`, или через `POST /printers/print/receipt`
с реальным `printer_id`, настроенным на IP этого принтера):

```python
from decimal import Decimal
from app.modules.printers.formatter import EscPosFormatter, ReceiptData, ReceiptLine

fmt = EscPosFormatter(paper_width=80, encoding="cp866")  # или 58; или "cp1251"/"utf-8" под свою модель
data = ReceiptData(
    company_name="Marjon Cafe", branch_name="Центральный", order_number="128",
    order_type="dine_in", cashier_name="Касса",
    items=[ReceiptLine(name="Плов Ташкентский с бараниной", qty=Decimal(2), price=Decimal(35000), total=Decimal(70000))],
    subtotal=Decimal(70000), discount=Decimal(0), tax=Decimal(0), total=Decimal(70000),
    payment_method="cash", cash_received=Decimal(100000), change_given=Decimal(30000),
    table_number="5", waiter_name="Иван",
)
raw = fmt.format_receipt(data, template={})  # template={} = все блоки включены дефолтами
```

Для кухни — `EscPosFormatter.format_kitchen_ticket(KitchenTicketData(...), template={})`.

Или полный путь через настоящий заказ: `POST /pos/orders` → `POST /printers` (с
реальным IP) → `POST /printers/print/receipt` / `/print/kitchen` (или
compat-роут `/printers/print/orders/{id}/receipt|kitchen`).

## Общее (оба чека, обе ширины)

- [ ] Кириллица читается без "кракозябр" — если нет, поменять `encoding` при
      создании `EscPosFormatter` (`cp866` / `cp1251`) под кодовую страницу
      конкретной модели (см. `EscPosFormatter._CODEPAGES`).
- [ ] Обрезка (`GS V A 3` — partial cut) реально отрезает бумагу.
- [ ] После чека нет "убегающей" пустой бумаги (проверить `LF * 3` — при
      необходимости уменьшить/увеличить в `format_receipt`/`format_kitchen_ticket`).
- [ ] `lineSpacing: "small"` заметно плотнее, чем `"large"`; `"medium"` —
      «дефолтная» плотность принтера (визуально между small и large).
- [ ] `weight: "bold"` реально жирнее обычного текста на этой модели.
- [ ] `size: "large"` — тем же по ширине, вдвое выше; `"xlarge"` — вдвое выше
      И вдвое шире (следующий блок ПОСЛЕ большого/жирного/центрированного —
      обычного размера, не жирный, прижат влево: проверить на блоке, стоящем
      сразу после `total`/`orderNumber` с `xlarge`+`bold`+`center`).

## Клиентский чек (80мм)

- [ ] Логотип: пропорции не искажены, не обрезан, помещается по ширине.
- [ ] Название заведения, адрес, телефон — каждый по отдельному тумблеру.
- [ ] Между шапкой (лого/название/адрес/телефон) и номером заказа — БЕЗ линии.
- [ ] Между номером заказа/столом/официантом/датой и таблицей блюд — ОДНА линия.
- [ ] Длинное название блюда переносится на следующую строку, не обрезается.
- [ ] Скидка/сервисный сбор/НДС появляются только когда > 0 и включены.
- [ ] «К ОПЛАТЕ» — визуально самая крупная сумма на чеке (дефолт `xlarge`).
- [ ] Способ оплаты — по-русски («Наличные»/«Карта»/…), не код `cash`/`card`.
- [ ] Нижний блок «НОМЕР ЗАКАЗА» — тот же номер, что и в шапке.
- [ ] Старое поле `footerText` (если было в старом шаблоне) НЕ печатается.

## Клиентский чек (58мм)

- [ ] То же самое умещается без потери контента (перенос вместо обрезки).
- [ ] Позиция блюда с `size: "xlarge"` на 58мм — имя блюда НЕ съедено нулевой
      шириной колонки (двухстрочный layout: имя, затем `x{кол-во} … {сумма}`).

## Кухонный чек (оба формата)

- [ ] Обычный (не отменённый) заказ: `#{номер}` без пометки «ОТМЕНА».
- [ ] Отменённый заказ (статус `cancelled`): `#{номер}` + «ОТМЕНА» под ним,
      обычный блок номера НЕ дублируется.
- [ ] Тип заказа / стол / официант / время — каждый по отдельному тумблеру.
- [ ] Блюда и модификаторы печатаются ВСЕГДА, даже если все тумблеры выключены.
- [ ] «Заказы (показать сумму)» выключено — сумм нет вообще ни у одной позиции.
- [ ] «Заказы (показать сумму)» включено — сумма равна реальной цене×количеству
      из заказа (сверить с клиентским чеком того же заказа).
- [ ] «Комментарий» гасит ОБА — комментарий к позиции и комментарий к заказу —
      одним тумблером.
- [ ] Баннер «! СРОЧНО !» НЕ печатается ни при каких сохранённых старых данных.

## Если что-то не совпадает с этим чек-листом

1. Найти соответствующий блок в `app/modules/printers/formatter.py`
   (`format_receipt` / `format_kitchen_ticket`).
2. Добавить/поправить юнит-тест в `tests/test_receipt_formatter.py`, который
   ловит именно это несовпадение (byte-level assertion на decoded-текст).
3. Поправить форматтер, прогнать тесты, повторить физическую печать.
